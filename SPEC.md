# URL Shortener Specification

This document defines the behavior of a URL shortener implemented with the Python
standard library only.

## 1. Purpose

Users submit an HTTP or HTTPS URL to receive a short code, then use that code to
look up the original URL. The core library must be usable by both tests and the web
server without external packages.

## 2. Base62

`src/base62.py` provides `encode(nonnegative_int) -> str` and `decode(code) -> int`.
The alphabet order is `0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ`,
and zero is encoded as `"0"`. Negative values, empty strings, and characters outside
the alphabet raise `ValueError`. Non-integer encode inputs and non-string decode
inputs raise `TypeError`. Leading zero characters are accepted while decoding.

## 3. Hash table

`src/hash_table.py` provides `HashTable`, a string-keyed mapping that resolves
collisions by separate chaining. Each bucket is a linked list traversed in insertion
order. Initial capacity is 8. When the load factor exceeds 0.75, capacity doubles
and entries are rehashed. Set `max_load=None` to keep the chosen capacity fixed
for chaining experiments. String keys use the polynomial accumulator
`h = (h * 31 + ord(char)) % capacity`. The implementation must not use Python
`dict`, `set`, or built-in `hash()`.

`set(key, value)` inserts or replaces; `get(key)` returns a value or raises
`KeyError`; `contains(key)` returns a boolean; `delete(key)` returns the removed
value or raises `KeyError`; and `len(table)` returns the number of entries.
Non-string keys raise `TypeError`.

`src/linear_probing.py` provides `LinearProbingHashTable` with the same mapping
interface and polynomial hash. Collisions advance one slot at a time with wraparound;
deletions use tombstones, and a full table doubles before accepting another entry.
`URLShortener(table_type="chaining" | "linear")` selects either implementation.
Both URL-to-code and code-to-URL mappings use that implementation. The two
mappings are kept in memory for the lifetime of the server.

## 4. URL shortener

`src/shortener.py` provides `URLShortener` with `shorten(url) -> code` and
`expand(code) -> url`. URLs are stripped of surrounding whitespace before parsing
and must have an `http` or `https` scheme and a host. A missing host, an invalid port,
whitespace in the authority, or an ASCII control character anywhere in the input
causes `ValueError`. Repeated submissions of the same normalized URL
return the same code. Codes are generated by encoding monotonically increasing integer IDs with
base62; hash values are never used as codes. Unknown or invalid codes raise
`KeyError`.

## 5. Web server

`src/server.py` listens on port 8000 by default. `/` displays a URL input form;
submitting it displays the short link and original URL. `/<code>` redirects to the
original URL. `/table` displays the URL-to-code mapping. It shows each URL's
Horner calculation and either its bucket's linked nodes or the slots visited
while finding it. `make serve TABLE=linear` selects linear probing. Valid
`X-Forwarded-Host` and `X-Forwarded-Proto` headers produce absolute short links;
local requests can use relative links. Unknown codes return 404 and invalid
form input returns 400. The server returns 413 for request bodies above 1 MiB.

## 6. Boundary cases

- Base62: zero, 61/62 transitions, multi-character values, negatives, empty input,
  invalid characters, and large integer round trips.
- Hash table: empty table, collisions, update, delete, missing keys, resize,
  last-bucket indices, and retrieval after resizing.
- Shortener: surrounding whitespace, repeated URLs, distinct case/path values,
  invalid scheme/host, unknown codes, and malformed codes.
- Linear probing: collision chains across the array boundary, lookup in a full
  table, expansion after filling the last slot, and lookup past a deleted slot.
- Web: home form, successful and invalid submissions, redirect, missing code,
  forwarded origins, and table inspection.

## 7. Probe experiments

The chaining experiment fixes the capacity at 4093 and varies the target load
from 0.25 to 4.00. The comparison fixes both capacities at 4093 and supplies the
same inserted and missing URLs to both tables at target loads 0.1 to 0.9. Count
compared nodes for chaining and inspected slots for linear probing, including
the first empty slot on a miss. The theory uses the actual load after rounding
the number of entries to an integer.
